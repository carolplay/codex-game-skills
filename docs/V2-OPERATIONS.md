## 工作节奏

一个角色定向执行一次 → 保存结果 → 修订动作/执行器并升版本 → 下个角色验证。持续补齐所有已知缺失日常，见visit-plan。稳定流程不反复测试；真实未完成的日常可按当前版本执行。固定批次内不热改，不由agent补做；agent只在批次之间采样新路径和维护宏。

开发采样与宏回放分开记录。单个动作成功不能推断整个类别全部覆盖；通过包含冷却/无可领项，需要与真实领取区分。未知出口、身份、系统权限、锁屏及窗口尺寸失败停批；业务偏差只有预定义有界退出确认主城后才继续。
