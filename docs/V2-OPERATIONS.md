# V2三班开发与运行

用户授权与机器时段以[PROJECT-CONTEXT](PROJECT-CONTEXT.md)为准；任务清单以最新catalog、action与班次manifest为准。本文只维护执行流程。旧技术记录已归档，正常班次不加载[历史快照](archive/wos-instructions-2026-11-03/README.md)。

## 启动与接续

1. 读取本地当前控制文件及其指向的游戏日／班次检查点、角色绑定和最新manifest。先按真实UTC游戏日定位；新日不沿用旧日唯一奖励证据，已结案旧班不重跑。控制文件与原summary冲突时核对真实证据，不能用计划或发布版本证明执行完成。
2. 运行`skills/play-whiteout-survival-macros/scripts/macro_package.py`离线校验，并用`scripts/project_storage.py --check`核验项目存储；触及PROJECT-CONTEXT的维护线先清理再启动，批内逐项检查新增量。若同线程已有执行，接续其检查点；其他执行者持锁时等待交接，不另开并发。提前几分钟唤醒可离线准备，按用户指定时刻开始输入，不因早到直接放弃本班。
3. 先从当前对话官方CUA只读观察维护、窗口和连接状态。允许输入且持真实`visit.lock`和lease后，正常重连、切号，核验ID与王国并完成档案→主城往返。准备锁释放后由本地后端重新取得锁、只读核验接续；不向子进程注入对话身份、令牌或批准状态。
4. 当前角色先执行固定版本的一批；所有参与角色串行先覆盖一遍，再集中补欠。跨班未执行项与当前同号任务合并一次实际操作，迟完成另记。显式用户deadline照办；无deadline时不套用旧30分钟、角色预算或Orchestrator时段。

## 宏、开发与覆盖检查

每批冻结实际包、组合、action及执行器版本和哈希，运行中不热换。稳定动作优先；新增、修复及出口未稳定的动作后置，同时保留真实业务依赖，例如体力餐→情报、游历结算→补给→新启动，`daily`置尾。

宏按已识别页面和声明的有界出口执行。失败记录action、步骤名与阶段、错误、已发送输入、断言结果、版本哈希和恢复出口，不自动保存失败图片。业务偏差恢复固定锚点后继续其他任务；未知出口停当前批次，由模型现场恢复。覆盖后按失败队列单独重跑对应任务，现场勘错和录制，修订升版本后另批定向验证；无需先用旧截图离线排查。验证以真实目标状态为准，模型补做不回填原宏通过。稳定流程不为测试重跑，真实收益恢复可用时照常执行。

运行画面、校准副本和OCR裁剪使用有界临时工作区，后端关闭清除；长期只留结构化结果与OCR日志。图片只有成为实际运行模板或有明确测试消费者的回归样本才显式保留，不按时间、版本、失败或报告引用全量归档。清理规则统一读本地素材README。

每号批次后模型检查日常任务栏及visit-plan面板外项目，将缺口分为脚本失败、次数不足、未纳入清单、冷却／解锁、证据不足。领奖后读取实际下一档；积分325档完成不等于所有日常收益清空。没有检查就记未知。

日内唯一奖励只沿用同一UTC游戏日的真实完成证据；catalog标day或组件passed不够。队列、普通捐献、免费招募、仓库、联盟礼物等可再次恢复可用，按当前次数和冷却推进。自动参团不代替本人主动巨兽：按当日缺口交错有界发起、核对体力与实际派出，再以本人获胜战报去重到十胜；角色收尾收取新战报奖励，见[巨兽规格](../skills/play-whiteout-survival-macros/references/npc-rally.md)。

## 故障与恢复

| 实际情况 | 处理 |
|---|---|
| 其他设备登录、普通断线 | 在机器运行时段直接正常重连，重核身份／窗口／页面后续检查点；用户明确叫停时让出。 |
| 已知业务偏差、普通弹窗 | 预定义出口确认锚点后继续；需要模型恢复则另记开发片段。 |
| 未知页或出口失败 | 停当前自动批次，模型可在有效环境识别和恢复，再另起批次；不要求必须等下一班。 |
| 身份、尺寸或显示拓扑变化 | 暂停自动输入，保留原始失败；重新核验身份及校准，必要时正常重开，另起批次，不能在原批次静默换映射。 |
| `cgWindowNotFound`／`noWindowsAvailable` | 归为窗口查找／输入路由失败，不能仅凭名称判锁屏、TCC或游戏卡死。可有界正常置前、重新绑定；仍失败时正常Quit并确认退出→实际路径重开→身份／主城往返→后端只读交接。 |
| 明确锁屏／系统权限／全局平台拒绝 | 停输入，关闭backend并释放锁和lease，记录未执行；按工具要求由用户恢复。下一唤醒只读预检，持续同一阻断不重复通知、不换入口绕过。 |
| 单项游戏动作被平台审核拒绝 | 停该动作和当前批次、保留原拒绝，不重试或间接执行被拒动作。仅当正常退出仍被允许、环境及恢复锚点已确认，才另起批次处理不受影响的已授权任务；范围不明或退出也拒绝则停止输入。 |

锁屏本身不代表用户撤权，也不证明工具可操作；依据当次工具结果处理。官方入口曾成功不代表本地进程永久获得锁屏能力。持续锁屏独立运行尚未验收；V3原生权限和WOS目标验收前不迁移生产。

窗口恢复使用本地已验证尺寸档，记录实际像素、原生／参考坐标、观察哈希和锚点结果；未知尺寸不能直接按比例放行。只读诊断可用`scripts/macos_window_metadata.swift`与`scripts/analyze_window_diagnostic.py`，按需采样、不请求输入权限，私有输出留local-data。故障日志采集有界，不因长时间诊断挤掉其他账号覆盖。

本机受限终端出现`trusted Node process exited unexpectedly`曾被证实为独立后端启动环境问题；正常本机环境启动可用。这与明确的平台拒绝不同，不能据该崩溃反复要求用户解锁，也不能借切换环境重试被拒动作。

## 收尾与报告

先关闭本批专用backend，再释放实际锁与lease，保存下一检查点。报告包含：应做分母、各号实际结果与覆盖缺口、包／组合／action／执行器版本哈希、真实领取与冷却、偏差／未执行／次数不足／缺失宏、证据和准备／执行／检查耗时。宏回放、模型补做、历史实证沿用分别计账；旧失败不回填为通过。未知token填null，宏内模型调用为0不等于整班零token。

三班、猎熊、截图维护复用既有调度器，不新建重复任务。维护不启用游戏；旧V1跟踪仅核对正式run_id报告和缺失followup，不恢复其排程。猎熊规则读[bear-hunt](../skills/play-whiteout-survival-macros/references/bear-hunt.md)，素材维护读本地素材库README。
