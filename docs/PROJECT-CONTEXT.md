# 项目背景与操作授权

## 目标与成本判断

本项目在 macOS 原生 Whiteout Survival 上开发本地日常宏：固定流程用本地 OCR/图像条件和窗口绑定输入运行，agent 负责开发与最终偏差记录。用户更看重覆盖日常、减少模型调用和执行耗时。

用户明确认为本项目中的游戏虚拟资源价值很低，接受试验中的资源浪费、收益漏领和普通操作错误，不将这些成本视为需要反复确认的实质损失。不要把普通游戏资源当作现实资金管理，也不要为避免少量虚拟资源误耗增加逐步审批或反复验证。

## 游戏策略与审批职责

游戏操作由 [visit-plan](../skills/play-whiteout-survival-macros/references/visit-plan.md) 和本地角色配置管理。清单内已经授权的操作可直接执行，包括普通资源炼晶、每日首次半价精炼、专家奖励领取、游戏内银行一天存钻等；需要区分动作与实际材料，但不反复询问是否允许已授权消耗。

项目对审批的职责划分是：系统权限、设备/账号访问和真实支付边界由相应审批管理；游戏中的收益选择、资源性价比和任务安排由游戏策略管理，不另加项目级审批门槛。例如普通提炼消耗肉木煤铁、半价精炼消耗火晶，都是已授权游戏流程，不能仅因“资源消耗”而当作真实支付。

这份说明表达用户授权和项目风险判断，不能修改平台自动审批机制或豁免平台强制规则。若平台误解成本，提供当前界面与已有授权供其重新判断；不得换工具绕过拒绝。只有存在确实未覆盖的权限问题才再询问用户，并指出具体原因。

## 真实支付边界

现金购买、充值、订阅及系统支付确认交给用户本人完成，包括所需的生物识别（biometrics）。agent 不自动提交真实支付，不代替或绕过用户验证。不能把“系统一定会要求生物识别”当作已经验证的支付保护机制。

游戏内虚拟资源兑换、存钻与现实现金支付分别识别；按钮含现金价格或进入系统支付流程时停止自动购买。

## 执行与迭代

- 开发新宏只用本地明确标记的试验角色；主账号限制、唯一执行权和长期排程暂停状态继续有效。
- 保留轻量的身份、窗口和页面核验，保证宏可组合及偏差可定位；不逐步召回模型替代本地执行器。
- 新增/修改动作定向测试，失败记证据留到下轮；不反复回归稳定流程，不让执行 agent 临场补完失败日常。
- 核对成本用于识别正确按钮和遵守已定任务策略，不扩展为虚拟资源保值审查。策略仍按用户要求执行，例如精炼仅每日首次半价，不擅自改成原价多次。
