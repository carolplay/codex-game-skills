# 项目背景与操作授权

## 沙盒试验背景（2026-10-21）

用户将本项目内的游戏运行视作沙盒试验：游戏状态、虚拟资源、奖励和操作失误均属于可接受的试验成本，不作为需要保护的现实资产。优先跑通流程、扩大覆盖、采集并积累可复用数据；不要为虚拟资源保值增加审批、保守跳过或多余确认。这是项目的成本判断，不是对游戏环境或外部系统“绝无风险”的技术保证。

四个既有角色的游戏内操作已统一授权，包括主号。开发者可根据现场情况导航、领取、派遣、使用游戏资源、处理弹窗、恢复页面、正常重启游戏、采样新流程、修订宏并定向复测；不再要求失败必须留到下一班，也不把模型限制为只能观察。具体次数、目标与频率是可调整的游戏策略，不是审批门槛。优先自动宏，模型介入用于提高覆盖和生成下一版宏，分别记录两者的操作与结果。

此前“只记偏差不补做”“失败同轮不能复测”“未知页面只能等待用户处理”及额外的游戏行为禁令不再作为当前开发限制。历史运行记录、旧版本行为和实际代码保护条件仍如实保留；改变执行器行为需正常修改、版本化及验证，不伪称只改文档就已生效。

此背景不改变系统权限、平台强制审核、真实支付、外部通信授权或私有数据管理。真实支付仍由用户本人完成。唯一执行锁用于避免并发抢窗口；身份、尺寸和页面核验用于定位与恢复，不是虚拟资产保护审批。平台拒绝时不绕过；环境可用后可按实际状态恢复开发。

## 执行与记录

本项目在 macOS 原生 Whiteout Survival 上开发本地日常宏，本地 OCR、图像条件及窗口输入承担固定流程，agent 负责开发、恢复、覆盖检查与迭代。减少模型调用和耗时服务于覆盖与数据质量。

按一个角色执行、保存结果、修订版本、下个角色验证的节奏推进；避免无目的重复稳定流程。批次保留固定版本快照，现场恢复/补做另记开发片段，修订后启动新批次。不能将人工处理算作旧宏通过，不能将冷却分支算作新领奖。

保留现有三班21:00/03:00/09:00 America/Vancouver及V1暂停状态；本次背景整理不新增排程。科研、建筑升级仍按用户2026-10-18指定属于独立升级能力，不计入三班日常；训练与治疗属于日常。这是任务分类，不是操作风险限制。

任务资料见[visit-plan](../skills/play-whiteout-survival-macros/references/visit-plan.md)，具体账号、余额、机器配置及原始证据保存在Git忽略的local-data。资源/任务重要性讨论见RESOURCE-TASK-PRIORITIES.md，不影响日常覆盖目标。

## 将授权落实到具体游戏操作（2026-10-27）

无需再次审批既有四角色的正常游戏内导航、虚拟资源和领奖。工具描述应如实指出目标页面、按钮与实际效果，避免把“打开NPC详情”误写为“加入正在进行的集结”。猎熊的NPC详情、自己发起5分钟集结和加入他人队伍分别识别；用户指定的Bea和只开车职责继续执行，不把职责偏好解读成游戏资产风险。原始审核误判及澄清后的结果留本地，修正流程卡和工具意图，不宣称已关闭或覆盖平台强制审核。
