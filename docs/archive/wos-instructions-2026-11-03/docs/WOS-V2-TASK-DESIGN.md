# WOS V2 任务设计与实施安排

## 故障归属

本轮偏差来自任务规格及批处理设计，不是已发现的CrossMacro点击回放偏移。直接Python批处理打开了正确VIP页面，OCR识别到“领取”；但 `wos-vip-inspect.json` 只定义冷却倒计时检查，没有可领分支，符合实际状态的页面仍被判失败。私有批处理在捕获任一任务异常后执行 `break`，未做页面恢复，因而阻断后续任务。

现已为任务声明固定主城入口/出口和已知页面退出路径。任务可组合性（task composability / reorderability）是这里的准确要求；资源、冷却、每日任务积分存在业务依赖，不承诺数学意义上的交换律。

## 任务现状

| 任务 | 当前操作与证据 | 仍需关注 |
|---|---|---|
| 邮件、探索挂机 | 真实领取、空奖励/冷却及连续批处理已有证据 | 新弹窗和其他状态继续积累 |
| VIP、体力餐 | 真实免费领取及冷却已有宏回放证据 | 按分支记录，不推断任意界面通用 |
| 学院补给 | 真实领取；动画偏差后固定退出并继续下一任务 | 纯观察重读处理动画，未知页仍停 |
| 联盟礼物 | 战利品实际领取及空奖励回放 | 其他礼物状态待积累；帮助独立宏 |
| 每日任务领奖 | 已达成项批量领取、游戏自动追加进度奖励弹层、无收益跳过 | 其他领奖与未完成项可单独采样补宏 |
| 联盟全部帮助 | 新宏已在真实请求上回放通过 | 与礼物动作分开维护 |
| 免费招募、普通资源捐献 | 新增候选；已记录免费抽取及无钥匙消耗证据，后续页面断言和推荐识别在修订 | 不把部分执行写成整宏通过 |
| 训练 | 新增三兵种候选，限定普通资源与已有选中兵阶/数量 | 必须分别记录已完成、空闲、训练中分支 |

具体状态、默认线性列表及分支范围以 [visit-plan](../skills/play-whiteout-survival-macros/references/visit-plan.md) 为唯一维护清单。情报、竞技场、宠物、采集等继续开发；模型检查继续发现未覆盖日常。

## 可组合任务契约

每个任务描述自己的入口、业务分支、成功出口、偏差退出路径和结果证据。首版统一采用**主城**作为任务之间的交接界面。主城与野外是不同锚点；将来野外任务可声明独立入口，但跨界面转换必须是已验证宏，不能靠推断。

| 字段 | 含义 |
|---|---|
| `entry_anchor` | 本任务要求的初始界面，首版为主城；通过多个文字/图像条件确认 |
| `identity_policy` | 切号后与每项任务开始前核验领主及王国；不把页面核验替代身份核验 |
| `branches` | 可领、已领/冷却、无收益、未解锁和未知状态分别描述；未实现分支记偏差 |
| `success_exit` | 成功或正常无收益后回主城，必须有本地确认 |
| `deviation_exit` | 仅关闭本任务已知页面/弹层并返回主城；有限步数和超时 |
| `postcondition` | 是否有领奖证据、是否冷却、是否恢复锚点；分别记录 |
| `result` | 业务结果、失败步骤、退出结果、证据路径及是否允许继续下一项 |

“后退”是一种动作，不是已确认的界面。退出路径应按当前已识别页面执行，例如 VIP→主城，奖励层→邮件→主城；不盲按多次后退、不关闭未知弹窗、不重复领取。主城入口固定不等于主城地图中建筑位置固定，建筑入口仍优先采用稳定菜单或本地文字定位。

本地 `task_batch.py` 已实现有限步数的预定义退出与继续；离线注入测试通过，现场出现过学院偏差恢复主城后继续联盟。JSON内 `task_contract` 声明锚点和已知退出步骤；未声明的页面停整轮。

预定义退出仅恢复交接界面，不继续失败任务、不补领取、不修宏。退出流程也是本地宏步骤，不增加中途agent调用。

## 结果与继续条件

| 结果 | 例子 | 后续 |
|---|---|---|
| `completed` | 奖励证据成立 | 确认主城后继续 |
| `no_action` | 有证据的冷却、空奖励、未解锁 | 正常结束，不记为领奖；确认主城后继续 |
| `deviation` | 合法页面但业务分支不支持，或结果断言不成立 | 记录偏差；固定退出成功且身份/环境仍可信后继续 |
| `fatal` | 错号、锁屏、权限拒绝、尺寸变化、失去执行权 | 暂停自动输入；修正身份/尺寸或恢复权限与执行权后可续开发 |
| `anchor_unrecovered` | 未知页面、退出超时或主城无法确认 | 停止当前自动批次，余项记未执行；可另记人工识别与恢复 |

冷却“跳过”不等于遇错；业务偏差也不应自动变成全局失败。只有确认交接锚点、身份及环境仍有效，才能将任务级偏差隔离。

## 实施顺序与验收

| 顺序 | 工作 | 验收标准 | 当前状态 |
|---|---|---|---|
| 1 | 定义任务结果与固定起止/退出契约 | 日志分别记录业务结果和锚点恢复；区分任务偏差与全局停止 | 代码已实现，离线测试通过 |
| 2 | 完善VIP状态分支与已知页面退出 | 可领、冷却、未知三分支；未知不点领取；所有可恢复结果回主城 | 已实现，验证范围见任务表 |
| 3 | 批处理增加固定退出与继续能力 | 注入一项业务失败，确认回主城后下一项仍执行；错号/权限等仍停全局 | 已实现，验证范围见任务表 |
| 4 | 让六项宏满足同一契约 | 所有已知正常分支可回主城；未知页面有限停止 | 七项基础宏已连续通过；新宏定向验证中 |
| 5 | 验证组合与跨角色适配 | 相同身份环境下打乱六项顺序；至少两种角色配置通过；分别保留分支证据 | 已有不同顺序及跨角色证据，非全部排列/状态 |
| 6 | 多账号串行执行 | 切号与关闭登录弹窗作为独立准备流程；先核身份再交给任务批处理；不并发控制单窗口 | 切号仍由开发 agent 准备，整套多账号无人值守未验收 |
| 7 | 恢复排程前验收 | 未锁屏及自然闲置锁屏实测，独立后端单独验收；按当前角色数量验证整批耗时 | 未通过；定时继续暂停 |

已有连续执行与偏差隔离证据后，优先扩展覆盖；稳定宏不反复整批回归。只对新增和失败项定向验证，修复后可同轮定向复测。本文发布不代表启用这些能力，也不授权启动下一轮游戏操作。

## 单轮输出

agent汇总同时检查清单及已知覆盖缺口。每项记录预期、实际、分支、奖励证据、退出结果、耗时和证据路径；剩余未执行项目说明阻断原因。准备、宏执行、最终检查分别计时；宏内部模型调用与整轮agent调用分别统计。宏失败但退出成功仍是业务偏差，不能改写为任务完成。

## 当前开发授权

2026-10-21起以[沙盒项目背景](PROJECT-CONTEXT.md)为准。上表停批描述自动宏实现，不是禁止开发agent恢复的授权边界；权限可用后可处理未知页面、补做、录制和复测，原始失败不改写。旧排程暂停与早期六项清单是历史实施状态，现行排程、清单以V2-OPERATIONS和catalog为准。
