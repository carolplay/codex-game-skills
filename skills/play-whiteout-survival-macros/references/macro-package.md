# 宏发布包与执行入口

WOS业务文件由本skill维护；CrossMacro提供通用执行器。身份、预算、机器路径、截图、完整录制与运行记录留在Git忽略的local-data。

当前包0.9.5，执行器最低0.2.7；47份动作文件（40个日常执行单元、4个独立情报组件、2个独立升级动作与1个档案工具）。动作版本不代表验收通过，范围以catalog、visit-plan与本地证据为准。主号与成熟角色使用同一完整当前清单，低等级按实际解锁；不再保留主号精简旧版。

- catalog.json注册动作路径、action_id/action_version、内容SHA256、周期、验证范围和未实现/部分覆盖项目。
- actions/维护唯一业务步骤；assets/只含可复用小图标，完整账号截图不公开。
- macros/shift-{1,2,3}.json固定顺序与动作版本/哈希；每项须纳入或声明排除原因，每日任务领奖置尾。
- scripts/macro_package.py离线校验包、哈希与各profile；默认不进行游戏输入。
- scripts/run_visit.py一次调用完整组合并冻结内存快照，显式--execute才运行；--tasks是开发定向入口，报告标为targeted-development，不冒充完整班次。

```sh
python3 scripts/macro_package.py
python3 scripts/run_visit.py \
  --executor-dir /path/to/CrossMacro/tools/macos-window \
  --manifest macros/shift-3.json --profile mature-test \
  --config /private/role-config.json --log-root /private/runs \
  --lock-file /private/visit.lock --guard-script /private/guard.py
```

追加--execute才输入。Orchestrator已取消，leader直接掌握窗口；仍须真实flock和本地lease完成准备→宏→准备/释放的串行交接，不能伪造空闲。后端保持一个，自动推进本地OCR/图像条件，不需agent操作CrossMacro编辑器。业务偏差预定义有界退出；全局身份/权限/锁屏/尺寸及未知出口失败停批。

执行器0.2.0支持局部OCR、严格数字读回、显式低置信数字阈值、领取后数字增长与纯观察重读、多个队列计时区域、校准红点、图标模板、有限方向键批量导航、声明式提前完成和跳过依赖。图像匹配使用NumPy与Pillow，在本地完成；模板由私有config的image_templates把语义名称映射到本skill assets绝对路径。缺模板或页面不明时失败，不猜点击坐标。旧的单一OCR目标默认仍必须唯一；只有动作明确声明select=top-left才从多个合法候选中选最上方。

发布动作修改时升对应action版本、重算catalog哈希、更新各组合pin并升组合及包版本。报告保留包/组合/action版本与哈希和执行器版本；不回写旧报告。开发按一个角色一次→修订→下个角色迭代，固定批次内不热改，不由agent补做。

编辑器导出的旧逐步.macro只代表当时快照，不自动获得新动作或退出逻辑。正式编辑器/调度可用一个Shell动作调用本入口。锁屏下独立CUA可信关联仍未验收，包存在和定时启用不表示长期锁屏可靠。

科研research和建筑construction保留在catalog与actions中，分类为progression/upgrade。三份shift清单的所有profile均明确排除，不计入日常分母；只按另行指定的升级目标调用。

0.2.2增加page_text_only：显式指定局部截图范围时，条件仅检查该范围的OCR；旧page_text_regions仍为整屏补充观察。用于NPC菜单与背景文字隔离，保留局部玩家控件排除，不因背景集结文字拒绝正确NPC。

0.2.3增加text_target.crop_ocr：在声明范围内对同一张截图放大OCR，再把局部坐标换回窗口坐标。用于整屏OCR漏读的资源分类文字；缓存只复用同帧结果，零个或多个匹配仍报偏差，不猜位置。包校验同时拒绝完全相同的退出前提，避免进入恢复时才发现多个出口匹配。

0.2.4支持同一语义模板绑定1至4份本地图案，取同帧限定区域内最高匹配分数；单一路径配置继续兼容。用于同类任务在不同等级/客户端皮肤下的图标差异。部署时`image_templates`中`intel-rescue`、`intel-hero`、`intel-beast`分别绑定原图与`assets/intel-*-low.png`的绝对路径数组；另绑定`island-life-bubble`到同名asset。无匹配仅说明已登记图案未出现，不能据此宣称所有日常完成；新皮肤需要最终偏差审计。

0.9.2把三类情报各跑一次改为`intel_cycle`：完成情报可能揭示队列中的其他类型任务，必须重新观察当前地图。动作通过`repeat_from`重复已声明尾部，每轮按火兽/普通野兽/营救/英雄检查，不设任务数量上限，只有当前匹配的分支执行，全部已登记图案都不存在时提前结束，总预算1800秒，仅作为卡死保护。普通三类与火兽独立组件保留用于开发，不与混合循环在同一班重复执行；清单数量减少2表示合并，不表示减少日常类别。未知图案、遮挡或体力不足仍记录偏差，不能凭无匹配宣称全部日常完成。

`actions/wos-intel-cycle.json`由`scripts/build_intel_cycle.py --output ... --version ...`生成。维护各组件的第一组任务步骤，再显式生成新版本、更新catalog与manifest pin。生成结果记录组件内容哈希；离线测试拒绝组件修改后忘记重建循环，避免手工维护数百步复制内容。

执行器0.2.5对已明确跳过分支的依赖步骤直接记跳过，不再逐步截图；下一个可执行步骤始终重新观察后才输入。单个动作预算仍必须显式且有界，最大1800秒；旧动作的现有短预算保留。

执行器0.2.7支持声明式循环尾部：必须显式超时、以观察和完成条件为循环入口；每轮步骤名及跳过依赖独立，避免上一轮无任务导致下一轮也被跳过。重复触摸方向键后逐次读取窗口状态，避免连续手势合并。生成脚本只输出一轮结构，运行时展开，不需要agent逐步调用。

0.9.3修正地心可扫荡标记搜索区域（包括窗口上方）并加入`labyrinth-available-upper.png`变体；本地别名绑定原图与此图，不能只更新workflow范围却漏部署图案。海岛回顶改为两段各最多20次手势，入口可见即跳过；旧版本误判空和定位失败均保留审计记录。

0.9.4将地心动作升至0.1.2：扫荡领奖后进入新关卡页时，旧返回箭头未回根页；保留业务偏差，另以明确“在此战斗＋首胜奖励”页面的右上X直接回主城。旧zone出口排除该页面，避免多个出口同时匹配。此出口开发操作及离线唯一匹配通过，下一角色宏回放待验。

0.9.5将海岛升至0.1.6：移除被光标遮挡的日常标签作为树入口的必要文字，使用树标题及概览页脚；主城明确排除该页脚。保存失败截图离线校准，不把偏差退出的旧误判写成已确认主城。现场下一角色待验。
