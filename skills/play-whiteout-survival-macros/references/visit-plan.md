# 三次日常与流程规格

当前运行仅执行固定清单中的已有宏 → 本地审计 → 一次最终检查并记录偏差。下表是必须逐步覆盖的日常任务及分时开发计划，可以拆分到三次访问或简化路径；“没做”表示开发缺口，不表示任务可省略。执行阶段仍只运行固定清单，未宏化项目由开发阶段补齐，不让执行 agent 临场补做。一天三次并不表示每项都重复三次。

| 项目 | status | 频率/分配 | 进入与操作 | 完成证据/分支 |
|---|---|---|---|---|
| 身份 | 已验证 | 每次、切号后 | 主城头像→领主档案 | ID与王国同时匹配；退出主城 |
| 邮件 | 已验证 | 每次 | 右下邮件→报告/系统/联盟各页→一键已读&领取 | 奖励层才证明新奖励；无奖励记无新收益；禁止删除邮件 |
| VIP | 已做 | 每日首轮领取，后两轮仅有异常才查 | 顶部VIP→每日免费礼包 | 有免费按钮才领取；倒计时表示不可领；下方现金礼包独立 |
| 探索挂机 | 已验证 | 每次 | 左下探索→领取→挂机收益→领取→关闭奖励 | 读取挂机时长、奖励层及按钮灰态；累计上限与领取间隔分别记录 |
| 情报 | 没做 | 每个刷新周期 | 灯塔→完成项→待做项；有体力和可用队伍再派 | 完成奖励、派出状态、队列/体力；悬赏与普通情报分记 |
| 免费体力餐 | 已做 | 每次核验当前窗口 | 档案体力+→获取更多→丰盛的招待 | 免费领取及体力增量/下次倒计时；不使用体力罐或钻石 |
| 训练/治疗/研究/建造 | 已做 | 每次 | 训练候选已建；概览定位兵营→收兵→普通资源续队；治疗/研究/建造仍没做 | 队列计时、目标与资源；不为清红点随意升级 |
| 联盟帮助/礼物 | 已验证 | 每次 | 联盟→帮助/礼物→可用的批量入口 | 帮助清空/礼物领取状态；不发聊天 |
| 联盟普通资源捐献 | 已做 | 每日固定一轮 | 联盟科技→推荐项→普通资源按钮 | 最多25次、每次1250；钻石数不变；其他成本停止 |
| 免费招募 | 已做 | 每日首轮，另按当前免费倒计时 | 英雄大厅→免费招募 | 免费文字和计数变化；有钥匙与免费需分别标明 |
| 每日任务宝箱 | 已做 | 每次尾部，最后一轮补满 | 任务→日常→已达成项与进度宝箱 | 活跃值和宝箱状态；没有达成不硬花钻石补 |
| 竞技场 | 没做 | 每日固定一轮 | 仅免费次数，按账号阵容策略 | 次数变化、战斗结果；未授权不买次数 |
| 宠物产出技能 | 没做 | 每日首轮；狼/獾实测23h，其他读取实际冷却 | 爪印→狼/獾等当前技能 | 数量和冷却；麝牛需衔接真实采集，建筑技能单独策略 |
| 曙光学院补给 | 已做 | 对应UTC08、16刷新后的两轮 | 概览游历补给→免费领取 | 数量与倒计时；1000钻石按钮不是免费 |
| 商店免费箱/活动免费档 | 没做 | 每日首轮集中 | 核验入口标题→明确免费项 | 箱开启/勾选/材料增加；现金/钻石项不点 |
| 采集 | 没做 | 每次离线前 | 空闲队列→安全/无人资源点 | 派出、负重、抵达与返程分别记；不攻击玩家 |

## 下一轮任务发掘与实现

1. 在试验角色上从现有红点和已启用通知找入口，核对页面标题、可领内容、冷却与下一次通知；红点用于发现任务，不把所有红点都当作免费领奖按钮。
2. 对不明规则查攻略，再用游戏界面核验；记录最短进入/领取/退出路径、实际资源成本和完成证据。
3. 已设置会出红点/通知的项目都按各自频率纳入日常，按三次访问归组；具体通知项目与上次处理时间留本地。
4. 优先把这些日常做成独立可组合宏；失败项记录后下一轮修订，稳定宏不反复整批测试。未实现任务保持“没做”，不以规划完成冒充宏完成。

以上为下一轮开发要求，未恢复定时或扩大当前执行清单。

## status 的含义

- **不知道要不要做**：是否纳入自动化尚待决定，执行时不擅自加入。
- **没做**：已确定要覆盖，但尚无对应本地action实现。
- **已做**：已有代码，可领/冷却等必要分支或跨角色连续回放尚未验收。
- **已验证**：已记录现场回放证据；必须同时注明验证了什么分支、角色范围，不能据此推断所有状态通过。

本表status描述开发进度，不是“今天是否已领取”。每轮完成/冷却/偏差/未执行单独写入本地运行日志；角色证据和身份留本地；主账号不作为试验号，仅试验角色承接新宏开发。本表是以后持续迭代的任务backlog。

## 当前线性 action 清单

当前批处理可以显式传入顺序；以下为默认顺序。调整顺序必须满足每项同样的主城入口/出口与账号预算。业务前后依赖仍需声明，不承诺严格交换律。

| 顺序 | action / 文件 | 本地线性步骤 |
|---|---|---|
| 1 | mail / `wos-mail-rewards.json` | 主城→档案核验→主城→邮件→报告批量领取→系统批量领取→联盟批量领取→主城；奖励层按需关闭 |
| 2 | vip / `wos-vip-inspect.json` | 主城→档案核验→主城→VIP→可领则领/冷却则跳过→验证冷却→主城 |
| 3 | idle / `wos-idle-rewards.json` | 主城→档案核验→主城→探险→挂机收益→领取或冷却跳过→奖励关闭→主城 |
| 4 | feast / `wos-stamina-meal.json` | 主城→档案核验→体力+→丰盛的招待→领取或冷却跳过→档案→主城 |
| 5 | academy / `wos-academy-supply.json` | 主城→档案核验→主城→概览日常→游历补给→免费补给→领取或冷却跳过→主城 |
| 6 | alliance / `wos-alliance-free.json` | 主城→档案核验→主城→联盟互助查看→联盟宝箱战利品/赠礼领取或空奖励跳过→主城 |
| 7 | help / `wos-alliance-help.json` | 主城→档案核验→联盟互助→全部帮助或无请求跳过→主城 |
| 8 | daily / `wos-daily-earned.json` | 主城→档案核验→主城→任务→每日任务→一键领取已达成项/无奖励跳过→主城；游戏自动追加的进度奖励弹层一并处理；不逐箱点击 |

以上为下一版基础批处理默认列表；招募、捐献及三兵种训练仍显式指定进行定向验证，不自动进入稳定清单。

| 候选 action | 文件 | 本地线性步骤 |
|---|---|---|
| recruit | `wos-free-recruit.json` | 主城→档案→英雄→招募→记录钥匙→只点免费→关闭英雄/奖励页→校验钥匙未变→主城 |
| donate | `wos-alliance-donate.json` | 主城→档案→联盟科技→绿色推荐标记→普通资源捐献至0/25→校验钻石未变→主城 |
| shield / lancer / marksman | `wos-training-{shield,lancer,marksman}.json` | 主城→档案→概览城镇→兵种定位→收兵/打开菜单→训练页→普通资源续队或训练中跳过→主城；每项独立宏 |

训练候选保留原已选兵阶与数量，只接受最多1200人；不自动晋升、改数量、加速或花钻完成。训练完成/空闲/训练中分支分别记证据。尚未实现治疗、研究和建造续队。

每日任务领奖通常放最后，才能领取本轮其他操作新达成的奖励。这是业务依赖，不因界面可重排就忽略。

每项有固定page-specific退出步骤；业务偏差只退出并记日志，恢复主城才执行下一项。未知页或退出失败停整轮；错号、锁屏、输入拒绝、窗口尺寸变化属于全局停止。退出不等于补做或重试领取。

这些固定步骤由本地执行器连续调用，不需要agent操作CrossMacro编辑器。开发阶段迭代代码和复测，执行阶段只运行本轮固定版本。

## 刷新与排程

社区攻略把每日重置列为 UTC00:00、情报列为 UTC00/08/16 三批。它们是规划线索，当前版本以游戏倒计时/说明为准。学院 UTC08/16 的双次补给、宠物23h冷却来自本地历史实测；不要套成全部玩法的统一时间。

本地排程应使用 IANA 时区转换，不能全年固定 UTC 偏移。三次访问分别覆盖三批情报；首轮集中每日一次项目，第二轮处理首批学院补给和积压队列，第三轮处理第二批学院补给、活动与任务补漏。错过某轮不应无界重做前三轮全部内容。

探索领取的约10分钟间隔只约束探索同类收益领取，不是整个游戏或执行器的等待。期间做其他任务。奖励上限（此前界面9小时）与领取间隔是不同字段，不互相代替。

## 实证与来源

- 本地实测：探索真实领奖与冷却回放已完成；邮件报告一键领取出现奖励层；VIP免费档见倒计时。新宏是否可稳定回放以单独运行日志为准，不能把手工试通当宏测试通过。
- [现有开源bot任务目录](https://github.com/AminulIslamSifat/whiteout-survival-bot)：用于了解任务拆分和入口，不直接移植其Android坐标/账号登录。其自动购买VIP策略不沿用。
- [社区日常攻略](https://www.whiteoutsurvival-community.com/en/daily-guide.html)：刷新分配的辅助参考，非官方保证；具体额度/时间仍读游戏。
- V1 `free-rewards.md` 保留学院、实验室、宠物、募兵所、律令所、体力餐与储值免费箱的实操细节；V2按需引用，不把所有材料兑换称免费。

## 版本与任务次数

巨兽、试炼等这里讨论的项目属于要覆盖的游戏日常，不归为可选的“角色自设要求”。可按三次访问拆分或简化执行路径，但必须完成对应日常要求。次数以当前游戏任务面板、重置与实际达成条件为准，不沿用旧攻略的固定数字；开发阶段将缺失动作纳入宏，执行阶段保持固定清单和仅记录偏差。

训练宏也不能只把“完成一批”当作兵种目标达成：逐兵种读取本轮目标、数量和层级；老低阶兵晋升与新训练分开记录。数量输入后必须读回确认再提交，避免键盘批处理未生效仍沿用旧值。
