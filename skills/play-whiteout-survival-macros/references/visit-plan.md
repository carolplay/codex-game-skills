# 三次日常与流程规格

每次保底：身份 → 邮件/免费收益 → 探索挂机 → 情报与队列 → 已完成任务领奖 → 离线审计 → agent 补漏 → 主城收尾。一天三次并不表示每项都重复三次。

| 项目 | 频率/分配 | 进入与操作 | 完成证据/分支 |
|---|---|---|---|
| 身份 | 每次、切号后 | 主城头像→领主档案 | ID与王国同时匹配；退出主城 |
| 邮件 | 每次 | 右下邮件→报告/系统/联盟各页→一键已读&领取 | 奖励层才证明新奖励；无奖励记无新收益；禁止删除邮件 |
| VIP | 每日首轮领取，后两轮仅有异常才查 | 顶部VIP→每日免费礼包 | 有免费按钮才领取；倒计时表示不可领；下方现金礼包独立 |
| 探索挂机 | 每次 | 左下探索→领取→挂机收益→领取→关闭奖励 | 读取挂机时长、奖励层及按钮灰态；累计上限与领取间隔分别记录 |
| 情报 | 每个刷新周期 | 灯塔→完成项→待做项；有体力和可用队伍再派 | 完成奖励、派出状态、队列/体力；悬赏与普通情报分记 |
| 免费体力餐 | 每次核验当前窗口 | 档案体力+→获取更多→丰盛的招待 | 免费领取及体力增量/下次倒计时；不使用体力罐或钻石 |
| 训练/治疗/研究/建造 | 每次 | 概览对应队列→领取→按角色目标续队 | 队列计时、目标与资源；不为清红点随意升级 |
| 联盟帮助/礼物 | 每次 | 联盟→帮助/礼物→可用的批量入口 | 帮助清空/礼物领取状态；不发聊天 |
| 免费招募 | 每日首轮，另按当前免费倒计时 | 英雄大厅→免费招募 | 免费文字和计数变化；有钥匙与免费需分别标明 |
| 每日任务宝箱 | 每次尾部，最后一轮补满 | 任务→日常→已达成项与进度宝箱 | 活跃值和宝箱状态；没有达成不硬花钻石补 |
| 竞技场 | 每日固定一轮 | 仅免费次数，按账号阵容策略 | 次数变化、战斗结果；未授权不买次数 |
| 宠物产出技能 | 每日首轮，23h冷却漂移则记下次时间 | 爪印→狼/獾等当前技能 | 数量和冷却；麝牛需衔接真实采集，建筑技能单独策略 |
| 曙光学院补给 | 对应UTC08、16刷新后的两轮 | 概览游历补给→免费领取 | 数量与倒计时；1000钻石按钮不是免费 |
| 商店免费箱/活动免费档 | 每日首轮集中 | 核验入口标题→明确免费项 | 箱开启/勾选/材料增加；现金/钻石项不点 |
| 采集 | 每次离线前 | 空闲队列→安全/无人资源点 | 派出、负重、抵达与返程分别记；不攻击玩家 |

## 刷新与排程

社区攻略把每日重置列为 UTC00:00、情报列为 UTC00/08/16 三批。它们是规划线索，当前版本以游戏倒计时/说明为准。学院 UTC08/16 的双次补给、宠物23h冷却来自本地历史实测；不要套成全部玩法的统一时间。

本地排程应使用 IANA 时区转换，不能全年固定 UTC 偏移。三次访问分别覆盖三批情报；首轮集中每日一次项目，第二轮处理首批学院补给和积压队列，第三轮处理第二批学院补给、活动与任务补漏。错过某轮不应无界重做前三轮全部内容。

探索领取的约10分钟间隔只约束探索同类收益领取，不是整个游戏或执行器的等待。期间做其他任务。奖励上限（此前界面9小时）与领取间隔是不同字段，不互相代替。

## 实证与来源

- 本地实测：探索真实领奖与冷却回放已完成；邮件报告一键领取出现奖励层；VIP免费档见倒计时。新宏是否可稳定回放以单独运行日志为准，不能把手工试通当宏测试通过。
- [现有开源bot任务目录](https://github.com/AminulIslamSifat/whiteout-survival-bot)：用于了解任务拆分和入口，不直接移植其Android坐标/账号登录。其自动购买VIP策略不沿用。
- [社区日常攻略](https://www.whiteoutsurvival-community.com/en/daily-guide.html)：刷新分配的辅助参考，非官方保证；具体额度/时间仍读游戏。
- V1 `free-rewards.md` 保留学院、实验室、宠物、募兵所、律令所、体力餐与储值免费箱的实操细节；V2按需引用，不把所有材料兑换称免费。

## 版本与任务次数

宏执行前应把“角色自设目标”和“游戏日常任务要求”分开。角色可能要求额外巨兽或试验次数，但任务面板的实际达成条件才决定日常积分是否完成。官方2026-07-06更新曾调整 Tundra Arms League 活动中每日/每周北极冰原巨兽集结任务次数（不是所有日常的统一改动），不把旧攻略次数写成永久条件。[官方更新说明](https://www.centurygames.com/whiteout-survival-wos-update/)。

训练宏也不能只把“完成一批”当作兵种目标达成：逐兵种读取本轮目标、数量和层级；老低阶兵晋升与新训练分开记录。数量输入后必须读回确认再提交，避免键盘批处理未生效仍沿用旧值。
