# 三班任务与周期规格

当前采用“一个角色定向执行一次 → 保存偏差 → 升版本修订 → 下个角色验证”。用户已授权四个既有角色同等使用当前宏，包括主号；不再给主号保留旧精简清单。低等级仅按实际解锁区别。Orchestrator已取消，本leader直接管理窗口，保留真实互斥锁和租约。游戏内操作无需逐项征求批准；真实支付由用户本人完成，平台强制审核仍有效。详见[项目背景](../../../docs/PROJECT-CONTEXT.md)。

开发与执行分开：开发可以发现红点、查攻略、采样新路径、生成/修订宏；单个固定批次内不热改、不由agent补做。稳定任务不反复测试。业务偏差只有通过预定义有界退出并确认主城后才继续；身份、权限、锁屏、尺寸、未知出口失败停批。

## 当前线性动作列表与版本

正式清单以catalog、actions与三份shift manifest为准；没有旧的默认六项/八项清单。当前包0.9.2，通用执行器最低0.2.7。主号与成熟角色清单相同；一班含VIP，二/三班不重复每日VIP。所有组合固定动作版本和SHA256，运行中的快照不热改。开发定向子集须标记targeted-development，不能冒充完整班次。

第三班成熟角色默认顺序：

mail → idle → feast → academy → travel_idle → alliance → help → recruit → expert → refined → crystal → bank → shield → lancer → marksman → donate → pet_wolf → pet_badger → pet_deer → store_free → arena → island → orders → intel_cycle → gather_meat → gather_wood → gather_coal → gather_iron → healing → enlistment → pet_treasure_claim → pet_treasure_dispatch → pet_alliance_treasure → alliance_incentive → labyrinth → npc_autojoin → travel_idle_claim → war_academy_commission → daily。

每个动作统一从主城进入并返回主城，实际步骤与有界退出见对应JSON。每日任务领奖置尾，NPC自动加入/采集的行军位依赖显式维护。界面可组合不等于资源效果严格交换律。

## 三班与周期

一班UTC00、二班UTC08、三班UTC16；当前温哥华17/01/09，实际转换保留IANA时区。班级任务按刷新/队列执行，日任务按UTC游戏日去重，周/四周/活动按实例与结算窗口。不是每个任务每班重复三遍。红点用于发现缺失任务，wiki/攻略帮助理解规则，再用实际界面核验。

下一轮按角色逐一推进，已完成/冷却证据用于防重复；新任务与真实未完成项目继续开发。失败保存版本、步骤、预期/实际及截图；修订后交下个角色，稳定流程不重复刷成绩。未知页退出失败停当前批次，开发维护恢复后仍可处理其余任务/角色。
