# WOS V2：宏执行，agent 检查

V1 纯 agent 技能仍保留在 `../play-whiteout-survival/`。V2 不替代其游戏知识与账号授权；按需读取 V1 的免费收益、账号策略与界面参考。

1. 从调用方读取目标身份、语言、窗口基准尺寸、当地时区、单次截止、资源授权和本机执行入口。私人身份、机器路径、排程均在本地配置。
2. 取得唯一游戏执行权，核验身份与主城。锁屏、输入被拒、尺寸变化、错号立即退出并记录。一个 Mac 游戏实例不同时运行多个角色或开发输入。
3. 具体实操和录制判据读 [流程卡](references/recording-cards.md)。按 [三周期任务表](references/visit-plan.md) 选择本次固定清单。读取宏目录中每项的实测状态；候选流程不算已支持。
4. 一次调用本地批处理。宏内部只做状态识别与固定输入；OCR、模板、音频反馈在本地运行，不逐步调模型。使用 CrossMacro 的 Shell 步骤复用编辑器和调度。
5. 读取离线审计结果，agent 只处理未支持任务和异常。输入不确定时不自动重复领取；先看当前状态。恢复时从已验证锚点开始，不重跑整轮。
6. 全部任务各记为：已完成、有证据的已领/冷却、未解锁、未完成或失败。补漏之后再检查主城、身份、队列和遗漏项，记录本次耗时与覆盖。

音效只作为动作响应候选；奖励变化、身份和付费边界仍需视觉证据。音频失效自动回退视觉。录音只捕获目标游戏进程，不混录系统或麦克风。

衡量时分开记录开发录制耗时、宏运行耗时、agent补漏耗时、本地截图/OCR次数、模型实际调用或可见轮次数。没有旧版同负载基线时，不输出精确调用减少百分比。未完成任务不得计为省时。

不现金购买、不聊天、不攻击玩家。普通资源和其他稀缺资源遵守账号预算。保留原有长期暂停，单次实验不自动恢复定时。

可用 `scripts/plan_visit.py --config <本地三轮配置.json> --output <本轮计划.json>` 生成固定清单。脚本只规划，不操作游戏或启用排程；它将尚未验证的宏分配给agent检查。按IANA规则转换当地时间，不自行假设未来每年都有夏令时切换。

计划中的 `macro_then_check` 表示只验证了部分分支或仅有检查能力：先运行固定宏，再根据本地证据处理领取分支或帮助请求。它不等同于该玩法已经全部自动化。
