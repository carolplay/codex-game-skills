# WOS V2：固定宏执行与偏差记录

默认运行目标为 `macro_only_record_deviations`。运行清单是已有宏，不是游戏全部日常任务。V1 `../play-whiteout-survival/` 原样保留，当前执行不沿用其补做日常目标。

1. 读取调用方指定的角色、一次实验清单、本地配置和截止时间，取得唯一执行权。必要的切号和身份/窗口核验属于准备阶段，单独计时；身份不符、锁屏、输入拒绝或尺寸变化立即停止并记录。
2. 一次调用已有宏的本地批处理或 CrossMacro CLI。程序自动推进所有步骤，本地 OCR/图像条件/可选音频验证，不逐步调用 agent，也不要求 agent 操作或截图 CrossMacro 编辑器。
3. 宏遇到业务偏差，由本地预定义退出步骤恢复主城并记录；锚点恢复成功才继续后项。错号、锁屏、输入拒绝、尺寸变化或未知退出页停整轮。agent 不现场补做、改宏重跑或用模型接管失败步骤。尚未现场验证的分支如在固定清单内，要保留验证范围标签，失败如实记录。
4. 每个角色固定批次结束且环境可用时，增加一次模型主动检查：沿左侧日常任务栏核对未完成项目和次数，再检查visit-plan中不显示于边栏的明确日常。与本批summary、action版本及实际领奖/次数证据对照，分类为脚本执行失败、执行次数不足、未纳入清单、冷却/未解锁或证据不足；不要只凭积分满或无红点判断全部日常完成。可进入页面观察及有限退出，不提交补做、领取、派遣或技能激活；新流程交后续开发宏化。全局锁屏/权限/身份/尺寸阻断时检查延期，不能绕过。
5. 保存偏差（宏/步骤、预期、实际、证据路径）和耗时、本地截图/OCR次数、模型响应统计；停止专用 worker 并释放执行权。记录“清单执行结果”，不宣称全部日常完成。准备、宏执行、最终检查分别计时。

偏差交给独立开发维护任务集中复核、调整宏并测试。执行对话不自行扩展为学习或补漏模式；维护频率另行约定，不因“定期”字样自行启用排程。

音效仅作为动作反馈候选；身份、奖励和付费边界仍需视觉证据。录音仅捕获目标游戏进程。输入不确定时不盲目重复领取。不现金购买、不聊天、不攻击玩家。普通/稀缺资源遵守账号预算。单次实验不恢复长期暂停的定时任务。

正式执行清单由 `catalog.json`、`actions/` 和 `macros/shift-{1,2,3}.json` 组成，见 [发布包与运行入口](references/macro-package.md)。先调用 `scripts/macro_package.py` 校验，再通过 `scripts/run_visit.py --manifest ... --profile ...` 一次运行整批；默认只校验，`--execute` 才执行。角色身份、预算和租约由本地配置提供。包、组合宏和action分别记版本，组合固定action哈希，报告同时保留执行器版本。

旧 `scripts/plan_visit.py` 仅兼容早期本地配置的离线规划，不能作为当前班次发布清单。未宏化项目记录覆盖缺口，部分验证候选保留分支标签，不转给agent补做。

流程语义和录制维护按需读 [流程卡](references/recording-cards.md)、[三周期任务资料](references/visit-plan.md)；这些资料不扩大当前执行清单。

开发维护时按 [任务组合设计](../../docs/WOS-V2-TASK-DESIGN.md) 完善固定起止界面与偏差退出；本地批处理已实现有限退出与继续，现场验证范围以任务表及本地日志为准。不要在执行阶段临时添加恢复动作。

任务可组合性是长期设计要求：固定入口、固定出口、依赖显式、偏差隔离；不承诺资源或冷却等业务效果严格可交换。开发维护以 [visit-plan](references/visit-plan.md) 的status和线性action清单为准，失败项放到下一轮维护，不让执行agent临场补做。

用户已明确允许四个既有角色（包括主号）使用当前版本参与开发验证；成熟角色用同一完整适用清单，低等级仅按实际解锁排除。开发节奏为一个角色定向执行一次→修订版本→下一个角色验证，不等待下一班才修订。优先补覆盖缺口，对新增/失败action做针对性验证，不反复整批测试稳定宏。

科研与建筑升级属于独立升级能力，不属于日常；保留action，但所有三班清单排除research/construction，不因空闲队列、红点或补日常而启动升级。训练和治疗仍在日常范围。用户明确于2026-10-18。

当前开发排序：稳定日常在前，新增/修复且缺少回归证据的动作放末段，业务依赖显式保留；每日任务领奖仍为最后。宏后模型检查可发现未纳入项目，但不自动扩张当前固定批次。
